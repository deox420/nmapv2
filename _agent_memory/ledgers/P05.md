## (A) DESIGN

### Problem
nmap's only machine-readable, structured output is XML (`-oX`). Modern tooling (SIEM, CI, dashboards,
jq pipelines) overwhelmingly consumes JSON. Today users must post-process XML (xmltodict, custom XSLT),
which is lossy and brittle. There is no stable, first-class JSON output. P05 makes JSON a first-class
citizen via `-oJ <file>` (and inclusion in `-oA`).

### Why a self-contained writer (not threading JSON through every emit site)
nmap emits XML inline across dozens of call sites (`xml_*` helpers). Threading a parallel JSON channel
through all of them is high-surface and regression-prone. Instead we add a **self-contained writer**
that reads from the already-populated in-memory structures (`Target`, `PortList`, `serviceDeductions`)
at three well-defined points:
  - run open  (nmap.cc, right after the XML `<nmaprun>` root is written, ~line 2007)
  - per host  (nmap.cc host loop, ~line 2331, after `printserviceinfooutput`)
  - run close (output.cc `printfinaloutput`, alongside `<runstats>`)
This mirrors how the XML tree is structured but keeps all JSON logic in one module.

### Files
- NEW `output_json.h` / `output_json.cc` — the writer + robust JSON string escaper.
- `nmap.cc` — add `-oJ` to getopt + `-oA`; open JSON file; call `json_run_open` / `json_host`.
- `output.cc` — call `json_run_close` from `printfinaloutput`.
- `Makefile.in` — add `output_json.o` to the object list.

### Schema (stable, documented in docs/improvements/P05.md)
```
{ "nmaprun": {
    "scanner":"nmap", "args":"...", "start":<epoch>, "startstr":"...", "version":"7.99SVN",
    "scaninfo": {...minimal...},
    "hosts": [
      { "status": {"state":"up","reason":"..."},
        "addresses":[{"addr":"127.0.0.1","addrtype":"ipv4"}, ...],
        "hostnames":[{"name":"localhost","type":"user|PTR"}],
        "ports":[ {"protocol":"tcp","portid":80,"state":"open","reason":"syn-ack","reason_ttl":64,
                   "service":{"name":"http","product":"...","version":"...","extrainfo":"...",
                              "ostype":"...","method":"probed|table","conf":10,"cpe":[...],"tunnel":"ssl"}} ],
        "os":{"matches":[{"name":"...","accuracy":95}]} },
      ...
    ],
    "runstats": {"finished":{"time":<epoch>,"elapsed":<sec>,"exit":"success"},
                 "hosts":{"up":N,"down":M,"total":T}} } }
```

### Security note (untrusted input)
Service banners, version strings, hostnames and CPEs come from the network and are untrusted. All strings
are passed through `json_escape()` which escapes `"` `\` and control chars (`\b\f\n\r\t` + `\u00XX`),
preventing JSON injection / broken documents from malicious banners. No fixed-size buffers on the
untrusted path (std::string).

### Test strategy (phase C)
Bring up an nginx container (HTTP) on localhost; run `./nmap -sV -p <port> -oJ out.json 127.0.0.1`;
assert: file is valid JSON (python json.load), has nmaprun.hosts[0].ports[0].state == "open",
protocol/portid correct, and runstats.hosts.up == 1. Also assert a banner with `"` is escaped (no parse error).
