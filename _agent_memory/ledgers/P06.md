# P06 — Exporters to security standards (SARIF / OCSF / STIX)

Status: IN_PROGRESS

## (A) DESIGN

### Problem
Nmap output (XML / now JSON via P05) is Nmap-shaped. Security platforms increasingly
ingest *standard* formats: SARIF 2.1.0 (code-scanning / CI surfaces, GitHub), OCSF
(SIEM/data-lake normalization), STIX 2.1 (threat-intel / CTI sharing). Today users
hand-roll converters.

### Approach
A self-contained, dependency-free Python tool `tools/nmap-export.py` that reads the
stable P05 `-oJ` JSON (file or stdin) and emits SARIF / OCSF / STIX. Building on the
JSON (rather than threading three complex schemas through the C core) keeps each
schema maintainable and isolated, and reuses the reliability/diagnostics fields.

Mapping (one finding per open port, host context attached):
- **SARIF 2.1.0**: a `run` with tool driver `nmap`, one rule `nmap/open-port`,
  `results[]` (level note) carrying host/port/protocol/service/reliability in
  `properties`, location via `logicalLocations`.
- **OCSF**: array of Network Activity findings (category 4 / class 4001) with
  src/dst endpoint, observables (port, service), severity, metadata.product=nmap.
- **STIX 2.1**: a `bundle` of SCOs — `ipv4-addr`/`ipv6-addr` per host,
  `network-traffic` per open port (dst_port, protocols), `software` per detected
  service. Deterministic uuid5 IDs for reproducibility.

### Files
- NEW `tools/nmap-export.py` (stdlib only).
- Doc `docs/improvements/P06.md`, test `tests/improvements/P06/run.sh`.

### Test strategy
Scan a real localhost HTTP service with `-oJ`, pipe JSON to the tool for each format,
and assert: valid JSON; SARIF has version 2.1.0 + a result for the open port; OCSF has
a finding with the port; STIX is a bundle containing an ipv4-addr and a network-traffic
object with the right dst_port.
