# P27 — Parser / memory-safety hardening

This proposal covers auditing and hardening Nmap's handling of untrusted network
input and the internal data structures built from it. The first fix under this
banner is a genuine, reproducible memory-corruption crash in upstream Nmap's
service-detection output path.

## Fix 1 — use-after-free / double-free of service CPE data (`serviceDeductions`)

### Symptom
With service detection enabled, scanning an open port whose service carries a CPE
(for example Python's `http.server`, which reports
`cpe:/a:python:simplehttpserver`) **together with at least one other port** in the
same run crashes Nmap:

```
Service Info: CPE: <garbage bytes>
free(): double free detected in tcache 2
Aborted
```

(or an outright segfault, depending on heap state). It reproduces on pristine
upstream Nmap; it is not introduced by this fork.

### Root cause
`PortList::getServiceDeductions()` fills the caller's `serviceDeductions` struct by
**shallow-copying** the port's service record:

```cpp
*sd = *port->service;   // sd->cpe now holds pointers OWNED by port->service
```

Callers (e.g. `printportoutput`) reuse one `serviceDeductions sd` across every port
in a loop. When a later port has no service, `getServiceDeductions` took the
"no service" branch and called `sd->erase()` to clean the struct — but `erase()`
*frees* `product`, `version`, the `cpe` strings, etc. Those pointers were the ones
just borrowed from the previous (open) port's still-live service record. They are
then freed again when the host is torn down (double-free), and read in the interim
by `printserviceinfooutput` (use-after-free, the garbage CPE above).

Valgrind pinpoints it precisely: an invalid `free` in `serviceDeductions::erase()`
called from `getServiceDeductions`, followed by invalid reads in `cpe_get_part`.

### Fix
Add `serviceDeductions::reset()`, which restores all fields to their defaults
**without freeing** (including `cpe.clear()` to drop the borrowed pointers), and use
it in `getServiceDeductions` instead of `erase()`. The struct never owns the
pointers it receives there — they belong to the `Port` — so it must not free them.
The two `erase()` call sites that operate on a `Port`'s *own* service record are
left unchanged, since freeing is correct there.

After the fix, the previously crashing scan completes cleanly and Valgrind reports
**0 errors**.

## Verification

Reproducible test: [`tests/improvements/P27/run.sh`](../../tests/improvements/P27/run.sh).
It runs `nmap -sV` over an open CPE-bearing service plus a closed port on localhost
and asserts the scan completes with no crash and no memory-error diagnostics.
