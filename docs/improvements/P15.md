# P15 — Probe diagnostics telemetry

## Description

When a scan returns a surprising result — a host that looks entirely filtered, a
sea of `open|filtered` UDP ports, a handful of opens among thousands of drops — the
operator is usually left asking *why*. Nmap exposes a per-port `reason` (with
`--reason`), but nothing that summarises, at the host level, what the scan as a
whole actually observed and how much to trust it.

P15 adds a **diagnostics** block to every host in the native JSON output (P05). It
aggregates, across *all* probed ports (including the consolidated ignored states),
the evidence behind the results:

```json
"diagnostics": {
  "state_counts":  { "open": 1, "closed": 6 },
  "reason_counts": { "syn-ack": 1, "reset": 6 },
  "reliability":   { "high": 7, "medium": 0, "low": 0 },
  "notes": []
}
```

- **state_counts** — how many ports landed in each state.
- **reason_counts** — *why* they did: the tally of `state_reason` values (e.g.
  `syn-ack`, `reset`, `port-unreach`, `no-response`). This is the core "what did the
  probes actually elicit" telemetry.
- **reliability** — how many port states were `high` / `medium` / `low` confidence,
  reusing the P14 scoring. A scan dominated by `low` is a scan to distrust.
- **notes** — derived, human-readable warnings, for example when the majority of
  probed ports returned no response (a signature of filtering, rate-limiting or
  blackholing), or when low-reliability states outnumber high-reliability ones.

Because it is computed from the in-memory results at output time, the diagnostics
add no extra packets and work with any scan type.

## Why this matters

- **Explainability:** results carry their own justification — a `filtered` verdict
  backed by `reason_counts: {"no-response": 998}` tells the operator the host went
  silent, not that nmap found 998 distinct facts.
- **Foundation for P26:** detecting rate-limiting / blackholing builds directly on the
  `no-response` tally and the derived notes.

## Examples

```
# Surface hosts that look like they are dropping probes
nmap -sU -oJ - 10.0.0.0/24 \
  | jq '.nmaprun.hosts[] | select(.diagnostics.notes | length > 0) | {addr:.addresses[0].addr, notes:.diagnostics.notes}'

# Distribution of why ports are in their state, for one host
nmap -oJ - 10.0.0.5 | jq '.nmaprun.hosts[0].diagnostics.reason_counts'
```

## Verification

Reproducible test: [`tests/improvements/P15/run.sh`](../../tests/improvements/P15/run.sh).
It scans a mix of open and closed TCP ports and asserts the tallies and reliability
buckets are correct, and (as root) that a host which stays silent produces the
derived "no response … may be filtering/blackholing" note.
