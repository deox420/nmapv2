# P05 — Native JSON Output (`-oJ`)

## Synopsis

```
nmap -oJ <file> [other options] <target>
nmap -oJ - <target>          # write JSON to stdout
nmap -oA <basename> <target> # also writes <basename>.json
```

## Description

For its entire history Nmap's only structured, machine-readable output has been
XML (`-oX`). XML remains fully supported, but the overwhelming majority of modern
tooling — SIEMs, CI pipelines, dashboards, and ad-hoc `jq` one-liners — speaks
JSON. Until now, consuming Nmap from those tools meant translating XML at arm's
length (`xmltodict`, bespoke XSLT), which is lossy, fragile, and an extra moving
part in every integration.

The `-oJ` option makes JSON a first-class Nmap output format, produced directly by
the scan engine from the same in-memory results that drive the XML and normal
output. It is emitted alongside the other formats, so `-oN`, `-oX`, `-oG` and
`-oJ` can all be requested in a single run, and `-oA` now also writes a `.json`
file in addition to `.nmap`, `.gnmap` and `.xml`.

Passing `-` as the filename writes the JSON document to standard output, which is
convenient for piping straight into `jq`:

```
nmap -sV -oJ - 127.0.0.1 | jq '.nmaprun.hosts[].ports[] | select(.state=="open")'
```

## Output schema

The document is a single JSON object rooted at `nmaprun`:

```json
{
  "nmaprun": {
    "scanner": "nmap",
    "args": "nmap -sV -oJ - 127.0.0.1",
    "start": 1781565305,
    "startstr": "Mon Jun 15 23:15:05 2026",
    "version": "7.99SVN",
    "hosts": [
      {
        "status":    { "state": "up", "reason": "syn-ack" },
        "addresses": [ { "addr": "127.0.0.1", "addrtype": "ipv4" } ],
        "hostnames": [ { "name": "localhost", "type": "PTR" } ],
        "ports": [
          {
            "protocol": "tcp", "portid": 80,
            "state": "open", "reason": "syn-ack", "reason_ttl": 64,
            "reliability": 10, "reliability_level": "high",
            "service": {
              "name": "http", "product": "nginx", "version": "1.27.0",
              "conf": 10, "method": "probed",
              "cpe": [ "cpe:/a:igor_sysoev:nginx:1.27.0" ]
            }
          }
        ],
        "os": { "matches": [ { "name": "Linux 5.x", "accuracy": 95 } ] }
      }
    ],
    "runstats": {
      "finished": { "time": 1781565311, "timestr": "...", "elapsed": 6.27, "exit": "success" },
      "hosts":    { "up": 1, "down": 0, "total": 1 }
    }
  }
}
```

Fields that Nmap could not determine are simply omitted rather than emitted as
`null`, so consumers should treat absent keys as "unknown". The schema mirrors the
structure of the XML output, easing migration for existing integrations.

## Safety

Service banners, version strings, hostnames and CPE strings are taken directly
from the network and are therefore untrusted. Every string written to the JSON
document is passed through an escaper that neutralizes `"`, `\`, and control
characters (`\b \f \n \r \t` and `\u00XX` for other control bytes). A hostile
service cannot break the document structure or inject additional JSON. The
implementation uses no fixed-size buffers on the untrusted path.

## Examples

```
# JSON next to the human-readable and XML output
nmap -sV -oA scan 10.0.0.0/24

# Just the open ports, as a stream of objects
nmap -sV -oJ - 192.168.1.1 | jq -c '.nmaprun.hosts[].ports[] | select(.state=="open")'

# Count hosts that came up
nmap -sn -oJ - 10.0.0.0/24 | jq '.nmaprun.runstats.hosts.up'
```

## Verification

Reproducible test: [`tests/improvements/P05/run.sh`](../../tests/improvements/P05/run.sh).
It stands up a real HTTP service on localhost and asserts that `-oJ` produces valid
JSON with the open port, full `-sV` service detection, and correct run statistics;
and it verifies that quotes, backslashes and control characters are escaped and
round-trip exactly, so untrusted input can never corrupt the document.
