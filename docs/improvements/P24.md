# P24 — Honeypot / tarpit / fake-response detection

## Synopsis

```
nmap -sV --script honeypot-detect <target>
nmap -sV --script honeypot-detect --script-args honeypot-detect.minopen=50 <target>
```

## Description

Honeypots (Cowrie, OpenCanary, Conpot), TCP tarpits (LaBrea-style), and deceptive
firewalls deliberately *falsify* scan responses to waste an attacker's time and
pollute their results. Their favourite trick is to make a large number of ports
look "open" — often returning identical or empty banners on every one. Stock Nmap
reports those as genuine open ports, which can badly skew an assessment.

The `honeypot-detect` NSE host script inspects the results Nmap already gathered and
reports whether the host is likely lying, with the concrete indicators it found:

- **Excessive open ports** — far more open TCP ports than a real host would expose
  (default threshold ≥ 30, `honeypot-detect.minopen`).
- **Uniform banners** — a large fraction of the open ports sharing one identical
  service signature (default ≥ 10 and at least half of the open ports,
  `honeypot-detect.uniform`). This also captures the classic "all ports open, no
  banner" tarpit / blackhole-accept pattern, where the shared signature is simply
  *unknown*.

Each matching indicator adds to a confidence score; the script emits a `LIKELY` or
`POSSIBLE` verdict together with the indicators and the open-port count, so the
result is useful both to a human reading the report and to tooling consuming the
host-script output.

Run it with service detection (`-sV`) for best results — that is what populates the
per-port banners used by the uniformity check.

## Relationship to P14

This is the host-level companion to the per-port reliability score (P14). Where P14
rates how trustworthy a *single* port-state determination is, `honeypot-detect`
looks *across all ports* for the collective signature of a host that fabricates
openness. Together they let an operator distinguish a handful of genuine, high-
reliability open ports from a wall of fake ones.

## Output

```
Host script results:
| honeypot-detect:
|   verdict: LIKELY honeypot / fake-response host
|   open_ports: 40
|   indicators:
|     excessive open TCP ports (40)
|_    40 ports share an identical service signature (ssh//)
```

## Verification

Reproducible test: [`tests/improvements/P24/run.sh`](../../tests/improvements/P24/run.sh).
It stands up a 40-port fake responder on localhost (uniform SSH banner) and asserts
the script returns a `LIKELY` verdict with both indicators, and — as a negative
control — that a normal single-service host is **not** flagged.
